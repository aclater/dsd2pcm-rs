# C interface

`crates/dsd2pcm-capi` builds `libdsd2pcm.so` (`.dylib`, `.dll`) and `libdsd2pcm.a` with
`cargo build --release -p dsd2pcm-capi`. The header is
`crates/dsd2pcm-capi/include/dsd2pcm.h`, generated by cbindgen from the crate (see
`cbindgen.toml`); its comments document every item. Static linking on Linux also needs
`-lpthread -ldl -lm`; `cargo rustc --release -p dsd2pcm-capi --lib --crate-type staticlib
-- --print native-static-libs` prints the list for other platforms.

## Rules

- The header needs C99 or later (`stdint.h`, `//` comments, designated initialisers in the
  `*_INIT` macros) or C++.

- Every function that can fail returns an `int` status: `DSD2PCM_OK` (0) or a
  `DSD2PCM_E_*` code. `dsd2pcm_last_error()` gives the message of the last failure on the
  calling thread (owned by the library, valid until the next failure on that thread); it
  starts with the kind of failure (for example `unsupported: ...`), so print it alone rather
  than after `dsd2pcm_status_str()`, which names a code.
- Every pointer is checked for NULL (`DSD2PCM_E_NULL`). A buffer always comes with its
  length; a NULL buffer is allowed only with length 0 where the function says so. A
  non-NULL pointer must be aligned for its type even with length 0.
- Output buffers must not overlap each other or any input; the library checks and returns
  `DSD2PCM_E_INVALID_ARGUMENT`. On any error nothing is written to the output buffers and
  structs, and `dsd2pcm_convert_file` leaves an existing output file as it was.
- No panic crosses the interface: each entry point catches it and returns
  `DSD2PCM_E_INTERNAL`.
- The only memory the caller frees is a converter, with `dsd2pcm_frames_free`. Strings
  returned by the library are static or owned by it.
- Paths are NUL-terminated. On Unix they are raw bytes, passed to the file system as they
  are (any encoding); on Windows and other systems they must be UTF-8
  (`DSD2PCM_E_INVALID_ARGUMENT` otherwise). A wide-character variant for Windows may come
  later. An empty path is refused.
- Every struct the library reads or writes starts with `uint32_t struct_size`, set to
  `sizeof` the struct as the caller compiled it; start from its `*_INIT` macro
  (`DSD2PCM_FILE_OPTIONS_INIT`, `DSD2PCM_FILE_REPORT_INIT`, `DSD2PCM_FRAMES_CONFIG_INIT`,
  `DSD2PCM_RUN_INIT`, `DSD2PCM_STATS_INIT`), which sets it and zeroes the rest. Output
  structs (report, stats) need it set too. See [ABI](#abi).
- Zero fields are the defaults, apart from the rate (and channel count): cutoff
  `DSD2PCM_CUTOFF_STANDARD`, filter `DSD2PCM_FILTER_DEFAULT`, 0 dB, all cores, no
  callback. Integer selectors (cutoff, filter, format, threads) are checked, never trusted.
- `filter` selects the filter and quantiser: 0 is the default (scarletbook-pcm 0.7.0's
  samples). `DSD2PCM_FILTER_PYSACD` (1) is pysacd's filter with its dithered quantiser
  (`Filter::Pysacd`): 88200 and 176400 Hz, standard cutoff only. Its dither is seeded per
  frame from the frame's index in the area: whole files count from their first frame, frame
  runs from `dsd2pcm_run.first_frame` (the index of the run's first frame; a run with no
  frame before it starts the area). The default filter ignores `first_frame`.

## Whole files

```c
int dsd2pcm_convert_file(const char *input_path, const char *output_path,
                         const dsd2pcm_file_options *options,
                         dsd2pcm_file_report *report /* may be NULL */);
```

Converts a DSF or DFF file (DSD64) to a 24-bit WAV file. `options` holds the rate (88200,
176400, 352800), cutoff, filter, gain (-120 to +24 dB), `threads` (0: all cores, 1: the
calling thread only) and an optional progress callback:

```c
typedef int (*dsd2pcm_progress_fn)(uint64_t done, uint64_t total, void *user_data);
```

It is called on the calling thread, once before the first block and after each block, with
the output samples per channel done and in all; a non-zero return stops the conversion with
`DSD2PCM_E_CANCELLED`. It must not unwind (C++ exceptions, `longjmp`) into the library.

The input, its rate, the options, the output size and the output path are checked before
anything is written. Refused with `DSD2PCM_E_INVALID_ARGUMENT`: an output that is the input
file (the same path, a symbolic link to it, or on Unix a hard link), a directory or a path
ending in a separator, and an existing device, FIFO or socket. An existing output file that
is not writable, or an output directory that is not, gives `DSD2PCM_E_IO`.

The WAV is then written to a new temporary file `.dsd2pcm-PID-N.tmp` in the output's
directory (created exclusively), synced, given the permissions of the file it replaces, and
renamed over `output_path` only on success; on Unix the directory is then synced too. On
any error, including a cancel, the temporary file is removed and an existing output file is
left as it was, so a partial WAV never appears under `output_path`. A symbolic link at
`output_path` is replaced by the new file, not followed. The owner, ACLs and extended
attributes of a replaced file are not kept. If the process is killed (SIGKILL, power loss),
a `.dsd2pcm-PID-N.tmp` file may remain; it is safe to delete. The library installs no
signal handlers.

`crates/dsd2pcm-capi/examples/convert.c` is a complete program:

```c
static int progress(uint64_t done, uint64_t total, void *user_data) {
    (void)user_data;
    fprintf(stderr, "\r%3d%%", total ? (int)(100 * done / total) : 100);
    return 0; /* any other value cancels */
}

dsd2pcm_file_options opts = DSD2PCM_FILE_OPTIONS_INIT;
opts.rate_hz = 176400;
opts.progress = progress;
dsd2pcm_file_report report = DSD2PCM_FILE_REPORT_INIT;
int rc = dsd2pcm_convert_file(argv[1], argv[2], &opts, &report);
if (rc != DSD2PCM_OK)
    fprintf(stderr, "dsd2pcm: %s\n", dsd2pcm_last_error());
```

## Frame runs

The C counterpart of `dsd2pcm::frames::Converter`: Super Audio CD frames (`channels x 4704`
bytes, channels interleaved byte by byte, earliest sample in the most significant bit) to
interleaved 24-bit PCM, a run at a time, with the frames before and after the run as
context. Any run with its neighbours gives the bytes of that run in a whole-area
conversion, and those equal `dsd2pcm_convert_file`'s.

```c
dsd2pcm_frames_config cfg = DSD2PCM_FRAMES_CONFIG_INIT;
cfg.rate_hz = 176400;
cfg.channels = 2;
dsd2pcm_frames *conv;
if (dsd2pcm_frames_new(&cfg, &conv) != DSD2PCM_OK) { /* dsd2pcm_last_error() */ }

dsd2pcm_run run = {
    .struct_size = sizeof(dsd2pcm_run),
    .before = prev, .before_len = frame_bytes,   /* NULL, 0 at the start of the area */
    .frames = data, .frames_len = n * frame_bytes,
    .after = next,  .after_len = frame_bytes,    /* NULL, 0 at the end of the area */
    .first_frame = index_of_first_frame,
};
size_t out_bytes = dsd2pcm_frames_output_bytes(conv, n, DSD2PCM_FORMAT_S24LE);
int rc = dsd2pcm_frames_convert(conv, &run, DSD2PCM_FORMAT_S24LE, pcm, out_bytes,
                                frame_clipped, n /* or NULL, 0 */, &stats /* or NULL */);
dsd2pcm_frames_free(conv);
```

- Frames in separate buffers: set `frame_ptrs` (an array of `frame_count` pointers, one
  frame each) instead of `frames`/`frames_len`. Setting both is an error.
- `DSD2PCM_FORMAT_S24LE`: 3-byte little-endian samples, ready for a WAV or FLAC writer.
  `DSD2PCM_FORMAT_I32`: sign-extended `int32_t`; `out` must be 4-byte aligned.
- `dsd2pcm_frames_frame_bytes`, `_samples_per_frame` (1176, 2352 or 4704),
  `_context_bytes` (the neighbour bytes the output depends on) and `_output_bytes` size the
  buffers; each returns 0 for a NULL handle.
- `frame_clipped` receives the clamped samples per frame (all channels); `stats` the
  channel count, the clamped samples per channel and their sum.
- After the first call a converter allocates nothing. Use one converter per thread: a call
  while another thread uses the same handle returns `DSD2PCM_E_BUSY`. Freeing a handle
  while another thread uses it is undefined.

`crates/dsd2pcm-capi/tests/minimal.c` is the smallest complete program (commands in
[Building from source](#building-from-source)), and `tests/smoke.c` uses every function.
Both run without arguments.

## ABI

- `DSD2PCM_ABI_VERSION` (1) in the header and `dsd2pcm_abi_version()` in the library name
  the ABI; a program can compare them at start-up. On Linux the shared library's SONAME is
  `libdsd2pcm.so.<ABI version>`, so a program linked against ABI 1 never loads another.
- The ABI version goes up on any incompatible change: a field removed, moved or retyped, a
  changed function signature, a changed meaning of a value.
- Compatible changes only append: new fields go at the end of a struct, new functions,
  constants and status codes are added. Zero in a new field means the old behaviour.
- `struct_size` makes this work both ways. The library refuses a size below the struct's
  0.1.0 size (`DSD2PCM_E_INVALID_ARGUMENT`, before reading or writing anything), reads only
  the fields it knows from a larger struct (a newer header), and writes only
  `min(struct_size, its size)` bytes of an output struct.
- 0.1.0 sizes, fixed for ABI 1 whatever fields are appended later (checked when the
  library is built, and by its tests):

  | Struct | 64-bit | 32-bit x86 Linux (i686) | other 32-bit (8-byte aligned `uint64_t`, e.g. Arm) |
  |---|---|---|---|
  | `dsd2pcm_file_options` | 48 | 36 | 40 |
  | `dsd2pcm_file_report` | 88 | 88 | 88 |
  | `dsd2pcm_frames_config` | 32 | 28 | 32 |
  | `dsd2pcm_run` | 80 | 44 | 48 |
  | `dsd2pcm_stats` | 64 | 64 | 64 |

  A struct from a caller built against an older header is read for its `struct_size` bytes
  and the fields it lacks are taken as 0.

## Building from source

The C library is built without the crate's `flac` feature: its whole-file conversion takes
DSD input only, and without FLAC reading it holds no third-party code, only Rust's standard
library (MIT OR Apache-2.0). `--features flac` adds it back.

From 0.1.3 on, each release has the source as an attested archive,
`dsd2pcm-0.1.3-src.tar.gz`: the tagged commit's whole tree, made with
`git archive --format=tar --prefix=dsd2pcm-0.1.3/ v0.1.3 | gzip -n -9` (the same command
gives the same tar, and with GNU gzip the same bytes). To pin and check it:

```
gh release download v0.1.3 -R aclater/dsd2pcm-rs -p 'dsd2pcm-0.1.3-src.tar.gz*'
sha256sum -c dsd2pcm-0.1.3-src.tar.gz.sha256
gh attestation verify dsd2pcm-0.1.3-src.tar.gz -R aclater/dsd2pcm-rs --signer-workflow aclater/dsd2pcm-rs/.github/workflows/release.yml --source-ref refs/tags/v0.1.3
tar -xzf dsd2pcm-0.1.3-src.tar.gz
cd dsd2pcm-0.1.3
cargo build --release --locked -p dsd2pcm-capi
```

A minimal program, `crates/dsd2pcm-capi/tests/minimal.c`, converts one stereo frame of
DSD silence. To build and run it on Linux, from the repository root:

```
cargo build --release -p dsd2pcm-capi
cc -std=c11 -I crates/dsd2pcm-capi/include crates/dsd2pcm-capi/tests/minimal.c target/release/libdsd2pcm.a -lpthread -ldl -lm -o minimal
./minimal
```

It prints `dsd2pcm 0.1.2: 2352 samples per channel, first byte 0`. To link the shared
library instead (its SONAME is `libdsd2pcm.so.1`, so it needs that name at run time):

```
ln -sf libdsd2pcm.so target/release/libdsd2pcm.so.1
cc -std=c11 -I crates/dsd2pcm-capi/include crates/dsd2pcm-capi/tests/minimal.c -L target/release -ldsd2pcm -o minimal
LD_LIBRARY_PATH=target/release ./minimal
```

## Binary releases

Each GitHub release has the C library built for nine platforms, next to the command-line
tool, each with a `.sha256` file and a build provenance attestation:

| Archive | Platform |
|---|---|
| `libdsd2pcm-0.1.2-x86_64-linux.tar.gz` | Linux x86_64, glibc 2.17 or later |
| `libdsd2pcm-0.1.2-aarch64-linux.tar.gz` | Linux aarch64, glibc 2.17 or later |
| `libdsd2pcm-0.1.2-i686-linux.tar.gz` | Linux 32-bit x86, glibc 2.17 or later |
| `libdsd2pcm-0.1.2-x86_64-linux-musl.tar.gz` | Linux x86_64, musl 1.2.3 or later (Alpine 3.17 or later) |
| `libdsd2pcm-0.1.2-aarch64-linux-musl.tar.gz` | Linux aarch64, musl 1.2.3 or later |
| `libdsd2pcm-0.1.2-aarch64-macos.tar.gz` | macOS 11 or later, Apple silicon |
| `libdsd2pcm-0.1.2-x86_64-macos.tar.gz` | macOS 11 or later, Intel |
| `libdsd2pcm-0.1.2-x86_64-windows.zip` | Windows x86_64, for MSVC |
| `libdsd2pcm-0.1.2-x86_64-windows-gnu.zip` | Windows x86_64, for MinGW-w64 gcc (MSYS2 MINGW64, msvcrt) |

An archive holds:

- `include/dsd2pcm.h`;
- the shared library: `lib/libdsd2pcm.so.1` with the link `lib/libdsd2pcm.so` (Linux,
  SONAME `libdsd2pcm.so.1`; with musl it needs only musl's `libc.so`);
  `lib/libdsd2pcm.1.dylib` with the link `lib/libdsd2pcm.dylib`
  (macOS, install name `@rpath/libdsd2pcm.1.dylib`, signed with a Developer ID and
  notarised);
  `bin/dsd2pcm.dll` and its import library `lib/dsd2pcm.dll.lib` (Windows, MSVC, C runtime
  linked in), or `lib/libdsd2pcm.dll.a` (MinGW-w64; the DLL needs only Windows' own DLLs);
- the static library: `lib/libdsd2pcm.a` (`lib/dsd2pcm.lib` for MSVC, built with the
  static C runtime, `/MT`); position-independent, so it can go into a shared library;
- `lib/pkgconfig/dsd2pcm.pc` (all but MSVC), relative to wherever the archive is
  unpacked; its `Libs.private` lists the system libraries the static library needs;
- `examples/minimal.c` (`crates/dsd2pcm-capi/tests/minimal.c`), `README.md`,
  `LICENSE-MIT`, `LICENSE-APACHE`.

The `1` in the file names is the ABI version (see [ABI](#abi)). Check a download, unpack
it, and build the example against it, from the folder holding the archive (Linux x86_64
shown):

```
sha256sum -c libdsd2pcm-0.1.2-x86_64-linux.tar.gz.sha256
gh attestation verify libdsd2pcm-0.1.2-x86_64-linux.tar.gz -R aclater/dsd2pcm-rs
tar -xzf libdsd2pcm-0.1.2-x86_64-linux.tar.gz
export PKG_CONFIG_PATH=libdsd2pcm-0.1.2-x86_64-linux/lib/pkgconfig
cc libdsd2pcm-0.1.2-x86_64-linux/examples/minimal.c $(pkg-config --cflags --libs dsd2pcm) -Wl,-rpath,'$ORIGIN/libdsd2pcm-0.1.2-x86_64-linux/lib' -o minimal
./minimal
```

The musl archives work the same way on Alpine (`apk add gcc musl-dev pkgconf`). On macOS
the same with the `aarch64-macos` or `x86_64-macos` archive, `shasum -a 256 -c` in place of
`sha256sum -c`, and `-Wl,-rpath,@executable_path/libdsd2pcm-0.1.2-aarch64-macos/lib`.
Static linking instead (Linux):

```
cc libdsd2pcm-0.1.2-x86_64-linux/examples/minimal.c $(pkg-config --cflags dsd2pcm) libdsd2pcm-0.1.2-x86_64-linux/lib/libdsd2pcm.a $(pkg-config --libs-only-l --static dsd2pcm | sed 's/-ldsd2pcm//') -o minimal
```

To install system-wide, copy `include/` and `lib/` under a prefix such as `/usr/local`; the
pkg-config file needs no change. On Windows, in a Visual Studio developer prompt in the
unpacked folder:

```
cl /I include examples\minimal.c lib\dsd2pcm.dll.lib
copy bin\dsd2pcm.dll .
minimal.exe
```

With MinGW-w64, in an MSYS2 MINGW64 shell (`pacman -S mingw-w64-x86_64-gcc
mingw-w64-x86_64-pkgconf`), in the folder holding the unpacked
`libdsd2pcm-0.1.2-x86_64-windows-gnu` folder:

```
export PKG_CONFIG_PATH=libdsd2pcm-0.1.2-x86_64-windows-gnu/lib/pkgconfig
gcc libdsd2pcm-0.1.2-x86_64-windows-gnu/examples/minimal.c $(pkg-config --cflags --libs dsd2pcm) -o minimal.exe
cp libdsd2pcm-0.1.2-x86_64-windows-gnu/bin/dsd2pcm.dll .
./minimal.exe
```

`-ldsd2pcm` takes the import library `libdsd2pcm.dll.a`; for the static library name
`lib/libdsd2pcm.a` and add `$(pkg-config --libs-only-l --static dsd2pcm | sed
's/-ldsd2pcm//')`, as on Linux. The library uses msvcrt, like Rust's
`x86_64-pc-windows-gnu`: use the MINGW64 environment, not UCRT64.

On musl, Rust links the C runtime into a program statically by default and then builds
no shared library; the release's musl C library is built with `-C
target-feature=-crt-static`, so its shared library links musl dynamically and its static
library's `Libs.private` is `-lgcc_s -lc`. For a fully static program on musl, link the
static library with `-static` and `-lgcc_eh -lc` in place of `-lgcc_s -lc`.

### Embedding the static library

The static library holds the Rust standard library's global symbols as well as the
`dsd2pcm_*` functions: over a thousand on Linux, a few hundred of which end up exported
from a shared library that links it plainly (the shared library `libdsd2pcm` exports only
`dsd2pcm_*`). To put `libdsd2pcm.a` into a shared library of your own (a Python extension
module, a plug-in) without exporting them, and without clashing with another Rust library
in the same process, hide its symbols:

- GNU ld, lld and MinGW-w64: `-Wl,--exclude-libs,libdsd2pcm.a`, for example
  `cc -shared -fPIC -o myext.so myext.c libdsd2pcm-0.1.2-x86_64-linux/lib/libdsd2pcm.a -Wl,--exclude-libs,libdsd2pcm.a -lpthread -ldl -lm`
  (or a version script that lists your own exports);
- macOS: list your own exports, one per line with a leading underscore (`_PyInit_myext`), in
  a file and link with `-Wl,-exported_symbols_list,exports.txt`.

The release workflow does this for every archive: it links `examples/minimal.c` and the
static library into a shared library with these flags, checks that only the program's own
function is exported, and runs it.

### Intel CET

On x86_64 Linux, every object in `libdsd2pcm.a` (glibc and musl) and the glibc
`libdsd2pcm.so.1` carry the CET shadow-stack property (`readelf -n` shows `x86 feature:
SHSTK`), so a program or extension built with `-fcf-protection` keeps its SHSTK mark when
it links the library, and glibc with shadow stacks enabled loads it. Stable rustc cannot
emit the mark: the release adds it to each object afterwards
(`.github/scripts/clib-shstk.py`, from scarletbook-rs), and links the glibc shared library
again from those objects with `-z shstk` (`.github/scripts/relink-shstk.sh`; the only
unmarked inputs of that link are glibc 2.17's `stat64` and `fstat64` wrappers from
`libc_nonshared.a`, a tail call each). The libraries are not marked for indirect branch
tracking (IBT): Rust's precompiled standard library has no `ENDBR64` instructions, so a
program that links the static library loses its IBT mark. Do not force it with
`-Wl,-z,ibt`. The musl shared library is not marked (musl has no shadow-stack support), nor
are the 32-bit x86 libraries.

## Checks

`crates/dsd2pcm-capi/check.sh`, from the repository root, checks that the committed header
equals cbindgen's output (cbindgen from `PATH`, or the binary named by the `CBINDGEN`
environment variable; install it with `cargo install cbindgen`), then builds and runs
`tests/*.c` and `examples/convert.c` under gcc and clang with `-Wall -Wextra -Werror`,
compiles the header and its init macros as C++11, and runs the smoke test and the leak loop
(`tests/leakloop.c`: create, convert and free on every path, many times over) under clang's
AddressSanitizer, LeakSanitizer and UndefinedBehaviorSanitizer (`ASAN=0` skips that). CI
does the same in the C library job. The Rust tests of the interface
(`cargo test -p dsd2pcm-capi`) cover NULL pointers, bad lengths and values, `struct_size`,
overlapping buffers, cancelling, busy and poisoned handles, allocation after warm-up, and
byte identity with the Rust API. They also run under Miri
(`cargo +nightly-2026-11-01 miri test -p dsd2pcm-capi`; CI: `sanitizers.yml`, weekly and on
pull requests that touch the interface), apart from those that use files or convert many
frames, which are marked as ignored under Miri, and under ThreadSanitizer (weekly).
[testing.md](testing.md) has the details and the latest results.
